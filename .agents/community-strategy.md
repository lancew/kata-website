# Community Strategy — Judo Kata Tournament Manager

**Version:** v1 · **Last updated:** 2026-09-30
**Source context:** `.agents/product-marketing.md` (v2)

## Assumptions (correct anything wrong)
- Solo founder; product has **no public download** yet (demos + supervised test events only).
- No existing first-party community or mailing list.
- Time available for community: assumed ~2–4 hours/week.
- Primary goal: **word-of-mouth + advocate recruitment** to get the first real events running.

## The strategic call: presence-first, not platform-first

Do **not** launch a Discord/Circle/forum yet. With no users and no download,
a new platform launches empty and dies. The judo kata audience already gathers in
existing places; the job now is to be useful there, recruit design partners, and
only build a first-party space once there's a reason to gather.

Build the first-party home as a **plain email list**, not a chat server. It's the
lowest-effort asset that survives platform churn and can host case notes and
updates.

## Shared identity

The community is not "users of our software". It is:

> **People who run and judge judo kata competitions** — the organisers, mat
> clerks, and referees who make kata events happen.

Reinforce that identity: recognise good event-running, share how others do it,
and treat members as peers in the craft, not customers.

## Where the community already is

| Space | Why | How to show up |
|-------|-----|----------------|
| **Reddit r/judo** | Largest English judo community; kata questions appear regularly | Answer scoring/running questions with real detail; link only when directly asked |
| **Facebook groups** (judo kata groups, national federation groups) | Where a lot of club organisers actually are | Join, answer questions, share event photos/notes |
| **National federation kata channels** (e.g. British Judo kata, EJU/IJF kata networks) | Decision-makers for adopting at events | Direct relationships via Lance's IJF/EJU network |
| **The app GitHub repo** | Technical/self-host audience | Issues + Discussions as a lightweight dev community |
| **LinkedIn** | Judo officials and federations; most-cited outlet for professional topics | Short articles: "How we ran kata scoring at X" |
| **Kata events themselves** | Where every organiser is physically present | Attend/demo; collect contacts; that's fieldwork, not networking |
| **Judo podcasts / YouTube** | Transcribed and cited; builds presence beyond the niche | Guest spots; post event walkthroughs |

## Founding cohort (recruit 10–20 by hand)

Do not open anything publicly yet. Personally invite:
- Organisers of the **2024 Silesian Open** senior categories (existing relationship).
- Anyone who has already had a **demo or supervised test event**.
- Kata judges and referees in Lance's IJF/EJU network who run national events.
- One or two respected kata coaches who can validate and amplify.

Make the ask 1:1 and specific: *"I'd like you to run it at your next event and tell me what breaks."* Design partners, not users.

## Core loop

One repeatable monthly action that produces content and recruits members:

1. An organiser runs (or trials) the system at an event.
2. Publish a short **"Kata Event Note"** — what the event was, how scoring ran, one
   thing learned (with permission). *This also fills the CRO social-proof gap.*
3. Share the note where organisers are (newsletter, LinkedIn, relevant group).
4. A reader asks a question or asks for a demo → new organiser → repeat.

Every decision should speed up that loop.

## Rituals (start small)

- **Monthly — Kata Event Note** (email + blog-form post). One per event run.
- **Monthly — "How do you run yours?" thread** in one existing community (rotate:
  r/judo, then a Facebook group). Ask, don't broadcast.
- **Quarterly — informal organiser call** (30 min, no agenda, share setups).
- **Per event — a case note + thanks** to the organising club.

## First-contact journey (post-demo)

After someone emails for a demo:
1. Reply within a day with a short call offer + the relevant case note.
2. Send a supervised-run plan for their event.
3. After the run, ask for a **one-line quote** and permission to name the event.
4. Add them to the email list and the "Event partners" list.

## Advocate program — "Event Partners"

Lightweight, no budget required:
- **Who:** organisers who've run a real event on the system.
- **Benefits:** listed as a partner, direct input to the roadmap, early features,
  co-marketing (we help promote their event), a named thank-you.
- **Ask:** run it, give feedback, and refer other organisers.
- **Track:** events run, referrals, quotes collected.

## Metrics and health (manual until analytics exists)

No analytics today, so start with countable signals in a simple sheet:
- Demo enquiries per week (from email).
- Events run / trials booked.
- Quotes/testimonials collected (currently 0 — the key number).
- Inbound mentions (Reddit/FB/LinkedIn tags).
- Repo stars/issues.
- Email list size and open rate.

Add GoatCounter (free, cookieless) to measure referral clicks from community posts.

Healthy early signs: questions get answered by you within a day; other people
start naming you in threads; one advocate refers another organiser.

## 90-day plan

**Days 1–30 — map and seed**
- List 15 named organisers and where each gathers.
- Join the 3–4 relevant existing spaces; lurk, then answer 1 question/week.
- Email 10 founding organisers with a specific ask.
- Set up a Buttondown (or similar) email list as the first-party home.

**Days 31–60 — produce and show up**
- Publish 2 Kata Event Notes from trials/supervised runs.
- Post 1 helpful, non-promotional thread per month in an existing community.
- Start collecting one-line quotes + event names.

**Days 61–90 — recognise and decide**
- Run the first informal organiser call.
- Launch "Event Partners" with the first 2–3 names.
- Decide (based on demand) whether a first-party space is warranted; if not, keep
  the email list + existing communities.

## What NOT to do
- Don't launch an empty Discord/Circle/forum.
- Don't drop links into judo groups without contributing first.
- Don't fabricate testimonials or logos.
- Don't treat federations and club organisers as the same audience — different ask.
- Don't optimise for member count; optimise for **events run**.
